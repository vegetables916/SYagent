# 智能体分片上传方案

## Context

用户希望在聊天中给 AI 智能体发送大文件（图片、文档），需要分片上传机制保证大文件传输的稳定性。存储使用 MinIO。

## 主流方案（业界标准流程）

### 整体流程

```
前端选文件 → 计算 MD5 → 调 init 接口 → 并发上传分片 → 调 merge 接口 → 完成
```

### 后端 3 个接口

| 接口 | 路径 | 作用 |
|------|------|------|
| 初始化 | `POST /api/v1/files/init` | 接收文件名+MD5，秒传检查，调 MinIO `create_multipart_upload`，返回 uploadId |
| 上传分片 | `POST /api/v1/files/chunk` | 接收 chunk 数据，调 MinIO `upload_part`，返回 etag |
| 合并 | `POST /api/v1/files/complete` | 接收 uploadId + 所有 part 信息，调 MinIO `complete_multipart_upload`，返回文件 URL |

### 前端核心逻辑

1. `File.slice()` 按 2MB 切分
2. `spark-md5` 计算文件哈希（用于秒传 + 断点续传）
3. 复用已有的 `limitConcurrency` 控制 3 并发上传
4. 上传进度 = 已完成分片数 / 总分片数

### 文件类型

- 图片：jpg/png/gif/webp → 发给多模态 LLM（HumanMessage 带 image_url）
- 文档：PDF/TXT/DOCX → 提取文本后发给 LLM

## 验证方式

1. Docker 启动 MinIO，确认 console 可访问 `http://localhost:9001`
2. 前端选择文件 → 看到分片上传进度条
3. 上传完成后，MinIO bucket 中能看到完整文件
4. 聊天中发送图片 → LLM 能识别图片内容
