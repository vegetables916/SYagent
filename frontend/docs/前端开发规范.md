【前端编码规约，本项目 React+TypeScript+Vite+Antd+Tailwind】
# 1 文件&目录命名
1. 文件夹：全部小写，kebab‑case短横线分隔，例：agent‑manage，components，hooks，utils；pages下页面文件夹短横线。
2. React组件文件：PascalCase大驼峰，例：AgentChat.tsx、LoginPage.tsx；组件内部导出组件名与文件名保持一致。
3. ts工具、api、hooks文件：小驼峰lowerCamelCase，useAgentChat.ts，agentApi.ts。
4. 资源图片、svg：kebab‑case，login‑bg.png。
5. 禁止拼音英文混合命名，拒绝无意义缩写；英文语义完整。

# 2 TypeScript / JS
1. 变量、函数、参数：小驼峰 lowerCamelCase；函数优先动词开头 get/add/update/delete/detail。
2. 常量：全部大写，下划线分隔 MAX_UPLOAD_SIZE。
3. 缩进2空格；逻辑块之间空一行；if/for/while必须写大括号，禁止单行省略大括号。
4. 字符串优先单引号；使用let/const，禁止var；优先async‑await，少用嵌套回调。
5. 禁止直接判断`xxx === undefined`，使用`typeof xxx === 'undefined'`。
6. 复杂逻辑抽成函数，条件嵌套不要超过3层；不要写超长三元表达式。
7. 提交前删除无用console.log调试代码。

#3 CSS / Tailwind
1. 自定义css类名 kebab‑case短横线；禁止id选择器写样式。
2. 尽量使用属性缩写；0后面省略单位，写0，不要写0px。
3. @apply合理使用；渐变、特殊阴影等tailwind不好表达的写原生css。
4. React内联style使用js小驼峰：backgroundImage、backgroundSize。

#4 项目目录约定（vite‑react）
src
├── api        # 请求接口，按业务拆分文件，方法加注释，和后端controller对应
├── assets     # 图片、字体、全局样式；业务资源import导入
├── components # 公共通用组件 PascalCase；模块内局部组件放在pages对应模块下components
├── constants  # 常量、枚举定义
├── hooks      # 自定义hooks useXxx
├── layouts    # 布局组件
├── pages      # 页面，每个页面一个文件夹
├── router     # 路由配置，路由path使用kebab‑case，路由懒加载
├── utils      # 工具函数
public         # favicon、大静态资源，直接/路径访问，不import

#5 Git提交规范（husky+commitlint）
提交消息格式 type(scope): 描述，冒号后面必须有空格
type可选：feat(新功能) fix(修复bug) chore(工程配置/依赖) docs(文档) refactor(重构) style(格式)
示例：chore: 配置@别名映射src路径

#6 React编码习惯
1. Props显式定义TS类型，不要any泛滥；尽量不用@ts‑ignore。
2. 组件拆分，一个文件不要代码行数过大；复杂计算抽useMemo，事件处理抽单独handler。
3. 优先受控组件；避免直接操作DOM。
4. import顺序：三方库 → 组件 → hooks → 工具函数 → 静态资源。
